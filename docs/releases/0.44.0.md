# RECarve 0.44.0 — PE evidence and bounded original-behavior comparisons

This release packages the completed PE investigation and reconstruction work since
0.43.1. The command, MCP entry and bundled skill remain `carve`; the project/package
name remains `reverse-engineering-carve`. REA and carve remain independent MCP
servers. This GitHub release does not publish the project to npm.

## What changed

- **Feature boundaries:** PE command-handler entry evidence, selected-function roots,
  dependency investigation, original IAT witnesses and unresolved-call guidance.
- **Data and resources:** source/target addresses and sections, read/write access,
  original-byte witnesses, conservative string/constants, mutable/unknown data,
  resource links and reviewed reconstruction data pins. Static leads are not promoted
  to confirmed UI dispatch or runtime dependency closure.
- **Instruction and ABI reviews:** original executable-byte ranges and imported REA
  instruction identities are bound to separately declared Windows x64 register ABIs.
  Inferred decompiler signatures and unverified semantics remain explicit.
- **Generated verification tasks:** reviewed initialization/helper entries, readonly
  buffers, pure outputs and initialized inout buffers, exact memory bounds, fixed
  alignment and fresh per-call allocation. Observations include EAX and full declared
  output arrays; pure-output unwritten bytes remain null, while untouched inout bytes
  retain caller contents. Harness failures never count as equivalent target errors.
- **Declared environment boundaries:** initialization-only no-argument predicate
  results0or1, exact call counts, initialization-only writes and full initialized-region
  hashes. Original CPU detection bodies are not executed by these substitutions.
- **Reproducible examples:** independent REA/Ghidra evidence and original AMD64
  instruction comparisons for owned sessions and a pinned third-party CRC feature.
  Examples also cover original-free module/MCP reuse and deliberately incorrect
  candidates. Engine downloads and analyzed third-party binaries are not bundled.

## Verification

The release is validated locally using the complete test suite, packed clean install,
independent MCP checks and actual REA integrations. Reproduce the newly exercised
integrations with a configured Ghidra/JDK/REA installation and Unicorn2.1.4 Python:

```sh
CARVE_PE_PYTHON=/absolute/path/to/python node scripts/check-release.mjs \
  --pe-sequence --pe-crc-dispatch
```

Final counts and the exact source-set hash are recorded in the release's attached
verification summary. The integration scenarios include:

- Owned readonly sessions:40sequences156steps.
- Owned pure output:24sequences87steps, including correct-count/wrong-bytes rejection.
- Owned initialized inout:24sequences89steps, including clearing-initial-data rejection.
- Third-party CRC:194manual-harness cases plus16generated sequences194steps across two
  declared CPU predicate outcomes and eight alignments. The complete2048cell initialized
  table and dispatch pointers are checked. Original CPU detection is not executed.

Other historical integrations retain their original reports and scopes; the above
command does not claim to rerun every Android, native or hardware-dependent case.
These comparisons cover supplied cases under declared harnesses, not universal
program equivalence, actual Windows UI/loader execution or whole-application recovery.

## Install and use

Download the `.tgz` asset, verify it against `SHA256SUMS`, and install it into a local
project, or clone this tag and build:

```sh
npm ci
npm run build
node dist/cli.js --version
```

Node22.19 in the22 line or Node24.11+ is required. Keep an existing REA server and
add a separate `carve` MCP entry using [the setup guide](../REA_COMPANION.md).
Private agent memory, local research, analysis outputs, downloaded engines and
original application binaries are excluded from the published snapshot/package.

## Direction and limits

Existing PE function verification is retained as a supporting logic layer. The next
development direction is evidence-backed front-end blueprints, beginning with one
Electron/Web feature and its data/interaction contract, then rebuild acceptance.
That direction is planned work; front-end blueprint extraction is not shipped by
this release. Missing server behavior and unsupported runtime details remain unknown.
